# Codebase Patterns

- Board-driven build: read `.build-kit/.slices/current_context.json` for the active
  context, then `<context>/index.json` for slice statuses. Pick the highest-priority
  "Planned" slice, mark it InProgress (locally and on the board), build it end-to-end,
  then mark it Done. One slice per run.
- Slice detail comes from the eventmodelers `slicedata` API
  (`GET /api/org/:orgId/boards/:boardId/slicedata?contextId=<id>`), not the minimal
  cached `slice.json` — re-fetch and persist the full object before trusting local files.
- Never build manually: dispatch to `build-state-change`/`build-state-view`/
  `build-automation` per the slice's `sliceType`.
- `.build-kit/CLAUDE.md` "First-time project setup" must run once, before the first
  build skill, in a brand-new project: resolve `pyproject.toml` TODOs, then create
  `src/<pkg>/__init__.py`, `application.py`, `main.py`, `tests/integration/conftest.py`,
  and fill README/mkdocs/docs TODO titles.
- Read-model complexity guide: a "count of related entities" view (e.g. subscription
  count) does not need a `found`/404 concept — expose the count as a derived property
  (`len(self.items)`) over an always-defined zero state, matching specs that expect
  200 + zero values for an entity with no prior events, not a 404.
